# 战败与结果记账

> 统一 C/D 失败画面、单场心情事件与任务恢复，避免结算处理器互相吞掉状态。

## 1. 模块概述

评价、舰队是否仍可使用、任务如何恢复是三个问题。C/D 使用同一红色 DEFEAT 画面；失败后当前舰队可能仍可使用，也可能因前排或后排全部沉没而由游戏自动切换。脚本不能把“没有弹窗”或“自律正在运行”当作本场胜利。

普通任务用非 S 结果的额外 10 点保护舰队最低心情估计。牺牲编队任务具有显式豁免，仍复用同一套结果识别。它们不应通过复制执行循环绕开记账。

## 2. 模块职责

负责确认结果、每场记账去重、区分弹窗正文，以及执行既有撤退/换队策略。

不负责从单张评价图推算各舰船剩余血量、从 A 评价推断具体沉船数，或替代真实模拟器验收。

## 3. 模块位置

```text
module/combat/result.py          # 单场上下文
module/combat/combat.py          # 公共识别、点击与心情事件
module/combat/auto_search_combat.py  # 自律寻敌恢复
module/handler/info_handler.py   # 排除无可用舰队弹窗的委托误识别
module/raid/                    # 正常共斗与沉船政策
module/coalition/               # 多轮联盟与沉船政策
```

`CombatResult` 保存结果；`Combat` 负责记录与调用恢复钩子；`AutoSearchCombat` 才决定主线地图上的撤退或换队。活动派生类只声明差异。

## 4. 核心入口

| 入口 | 用途 |
| --- | --- |
| `combat_result_reset()` | 在普通战斗或自动搜索战斗入口重置本场状态 |
| `combat_result_record()` | 记录等级/确定战败，最多额外扣减一次并调用恢复钩子 |
| `handle_combat_defeat()` | 处理 C/D 共用红色失败画面 |
| `combat_result_observe()` | 自动搜索或联盟只观察结果，不点击 |
| `auto_search_combat_status()` | 关闭弹窗、推进结算并执行地图恢复 |

## 5. 核心组件

| `CombatResult` 字段 | 含义 |
| --- | --- |
| `fleet_index` | 本场画面舰队编号，决定心情账本与换队目标 |
| `emotion_reduce` | 是否允许本场额外心情记账；与联盟基础消耗开关分开 |
| `rank` | 已识别的评价；未知保持 `None` |
| `defeated` | 已通过共用失败画面或无可用舰队正文确认战败 |
| `shipwreck_reduced` | 本场是否已调用额外扣减，防止重复画面重复扣减 |

## 6. 工作流程

1. 战斗入口创建新上下文；确认进入战斗后按任务规则扣基础心情。
2. S/A/B 由现有评价或经验区域识别。C/D 字母颜色只作为进入结算的信号，动画误匹配不能直接确认失败。
3. 红色 DEFEAT 画面统一调用 `handle_combat_defeat()`，先记录，再按冷却点击关闭。沿用的资源名称 `OPTS_INFO_D` 不表示只有 D 使用它。
4. 若出现无可用舰队正文，记录战败并点击专用确认，继续截图等待游戏自动切换。正文模板避开动态舰队名称。
5. 没有该弹窗也保留战败状态，按用户策略处理仍可使用但已受损的当前舰队。
6. 撤退必须回到选关页才算完成；换队必须确认另一队编号后才允许开启自律。

## 7. 调用关系

主线、活动、三油和紧急委托经 `CampaignBase` 使用公共结果层。正常共斗经 `RaidCombat` 使用普通战斗入口；联盟每个内部战斗经自动搜索执行入口建立自己的结果上下文，再由活动循环推进下一轮。

`RaidScuttleCombat` 和 `CoalitionScuttleCombat` 豁免额外心情。联盟通过 `auto_search_defeat_recovery=False` 自行推进活动，不执行主线地图撤退策略。

## 8. 数据流

```text
新截图 → 正向结果识别 → CombatResult → 可选额外心情扣减
                                      → 首次确定战败 → 任务恢复钩子
心情扣减 → Emotion.reduce() → Value / Record / RecoveryState 原子保存
```

## 9. 状态模型

`defeated` 和 `shipwreck_reduced` 在一场内只从假变真。重复失败画面、评价页和经验页共用同一状态，下一场才重置。

自动搜索的 `_withdraw` 表示恢复待处理。`switch_confirmed` 必须来自目标舰队编号的正向识别；自律开关或确认按钮不能单独证明换队成功。

## 10. 配置与任务政策

| 场景 | 基础消耗 | 非 S / 确定战败额外消耗 | 后续流程 |
| --- | --- | --- | --- |
| 主线/活动/三油/紧急委托 | 每场 2，双倍书 4 | 每场最多 10 | 自律寻敌按 `Campaign.DefeatWithdraw` |
| 正常共斗 | 每场 2，双倍书 4 | 每场最多 10 | 共斗结果与任务循环 |
| 共斗沉船 | 每场基础消耗 | 豁免 | 原沉船任务循环 |
| 正常联盟多队 | 整关一次基础消耗 | 每个内部战斗最多 10 | 活动自行进入下一轮 |
| 正常联盟单队 | 每个内部战斗扣基础消耗 | 每个内部战斗最多 10 | 活动自行进入下一轮 |
| 联盟沉船 | 整关一次基础消耗 | 豁免 | 保留 `SCUTTLE_CONFIRM`，SP 需明确 S 才按成功收尾 |

`Emotion.Mode=ignore` 完全不记账；`calculate` 和 `calculate_ignore` 正常记账。`Emotion.IgnoreShipwreck` 仅豁免额外 10 点，公共心情沿用同一套事件。

S 不额外扣减；A 包含慢速胜利，无法从等级区分是否沉船，默认也扣 10。此处是保守估计，不表示游戏对所有舰船都扣了 10。未知等级不假定 S，也不凭未识别画面制造扣减事件。

`Campaign.DefeatWithdraw` 三种策略：

- `withdraw_continue`：每次战败撤退后继续任务。
- `withdraw_stop`：每次战败撤退，连续三次后确认退出关卡，再禁用当前任务。
- `switch_fleet`：仅确认另一队编号后恢复自律；没有另一队或切换超时则撤退。

## 11. 异常与错误处理

正常撤退抛 `CampaignEnd`；三次连续战败停止抛 `ScriptEnd`。未知画面仍由既有 `GameStuckError` / `GameTooManyClickError` 保护，不能因为结算超时就盲点失败按钮或编造战败。

## 13. 缓存与持久化

单场结果只在当前任务实例内保存，不写入用户配置。基础与额外扣减通过现有 `Emotion` 账本持久化，不另建恢复模型；不使用真实用户配置做回归测试。

## 14. 生命周期

`combat()` 或 `auto_search_combat_execute()` 重置结果，执行与结算阶段持续补充正向证据，任务恢复结束后由下一场重置。联盟多轮不能把第一场的去重标记沿用到后续战斗。

## 15. 扩展方式

新任务复用公共入口；额外消耗豁免覆写 `combat_shipwreck_emotion`，联盟基础消耗覆写 `coalition_emotion_reduce()`，专用确认通过 `coalition_result_confirm_buttons` 声明。新增结果布局需提供真实截图识别，不能把通用确认按钮当作等级。

## 16. 修改注意事项

- 委托与舰队失效弹窗共享蓝色「确定」位置，必须先识别正文。`handle_urgent_commission()` 对已知舰队失效正文返回 `False`，由战败流程操作。
- 换队按画面编号 `fleet_show_index` 计算目标，不能使用舰队顺序反转后的道中/Boss 角色编号。
- 记录状态不带点击冷却；操作才带间隔。所有结果处理器 `True` 仍只表示已操作。
- 保留掉落记录的 7 秒评价点击窗口；移除固定休眠后用冷却控制点击节奏。

## 17. 已知限制

本次无可用舰队正文素材来自 CN 1280×720 原图；其他语言正文尚无对应截图验收。评价颜色、动画和共斗/联盟特殊布局仍需真实模拟器覆盖，离线回放不能证明账号中所有活动版本均已验收。

客户端 Lua 的 `BattleDataProxy` 评分逻辑区分超时与舰队失效，`LevelStageView.CheckFleetChange` 在队伍失效后显示自动换队提示，普通关卡 `FinishStageCommand` 使用沉船能量扣减。评分名称不作为恢复分支依据；服务端专属活动消耗不能仅凭客户端未出现某个调用证明。

## 18. 实机验收场景

| 场景 | 应观察到的结果 |
| --- | --- |
| C/D 战败，前排或后排全沉 | 正确关闭失败页与无可用舰队弹窗，没有“紧急委托”误日志 |
| C/D 战败，当前队仍可使用 | 即使没有换队弹窗也执行策略，不让受损当前队自动再战 |
| 游戏自动换到另一队，配置换队 | 识别目标编号后恢复，不再次切回原队 |
| 撤退停止连续三次 | 每次先退出地图，第三次再停止任务 |
| 普通 S/A/B 与重复经验页 | S 只有基础消耗；A/B 最多额外扣一次 10 |
| 正常/沉船共斗与联盟多轮 | 基础消耗次数正确；沉船任务无额外扣减，专用确认不丢失 |

## 19. 调试方法

运行 `uv run python -m unittest tests.test_auto_search_defeat tests.test_combat_results`。截图夹具调用正式识别器；虚拟时钟和符号帧覆盖状态流转。先查 `[战斗-结算] 已确认战败结算`、`[战败计数]`、点击按钮及心情基础/额外扣减日志，再核对恢复后的舰队编号与自律开关。
