# 舰船数据重构验证记录

本文记录最初重构阶段的验证结果，后续已移除逐副本历史证据；现行行为以舰船数据说明为准。

日期：2026-10-26。基线为用户本人 deploy 修复后的开发分支。计划见 [固定重构计划](fleet-data-refactor-plan.md)，当前行为见 [舰船数据](fleet-analysis.md)。

## 实现结果

- 四个平级页面，仅挂载当前页；扫描及导入统一在扫描更新。
- 当前物理舰船与累计科技分离，schema v4 原位事务迁移。
- 三态里程碑、明确纠错冲突、退役保留进度与历史依据。
- 共用详情编辑器及带版本的会话草稿，明确区分经验未知与零。
- 待确认结果禁止覆盖，副本歧义逐项处理，移除单独确认。
- 具体副本养成方案支持 120/125 级，经验及资源估算说明，条件不改写事实。
- 跨页面带入选择仅应用一次；刷新保持后续选择，按实例保存方案。

## 真实数据迁移

对 `runtime-data/backend-20261026` 的独立副本执行迁移，原始输入挂载只读。原 archive、解压后的 deploy 工作区和原始数据均未修改。

| 项目 | 迁移前 | 迁移后 |
| --- | --- | --- |
| 物理舰船记录 | 991 | 991，原 ID 及全部原字段逐项一致 |
| 当前舰船种类 | 860 | 860 |
| 有科技奖励的已获取种类 | 762 | 762 |
| 已确认 120 级里程碑 | 537 | 537 |

点数差额 6,671 对应 128 种原来仅凭等级推断满星的舰船：科研 46 种、META 51 种、原生 UR 31 种。新规则将缺乏明确突破证据的满星改为未核实，保留原记录供核对。已有明确人工值被保留。普通舰船仅在突破未知时才按适用等级上限推断；明确突破阶段优先。

验证包括 SQLite 完整性、外键检查、原舰船字段、旧科技原始表、阵营记录逐项比对及迁移后只读载入不再改变文件。每种舰船的变化明细在开发运行目录 `validation/fleet-data-refactor/migration.json`，不将账号数据副本提交到代码仓库。

## 自动验证

后端使用现有 Docker 镜像 `alas:verify-fleet-upstream-20261025` 中 Python 3.14.6，配置和游戏数据使用临时目录或只读输入。

- 舰船、扫描、科技、数据库、心智及 OCR 专项共 407 项通过。
- API 与养成计算检查共 64 项通过。
- 最后的明确突破优先规则由 25 项针对性回归通过。
- 最后的养成身份、同名群组、经验及觉醒边界由 10 项独立专项复核通过。
- 前端 434 项单元测试、TypeScript 检查及生产构建通过。
- 两个科技浏览器场景验证纠错冲突、累计状态、退役及历史依据。
- 15 个页面浏览器场景覆盖四页导航、逐卡编辑、导入确认、单独移除、草稿、养成范围、试算、实例隔离、版本冲突、移动端和旧路由。

浏览器组合运行先通过 14/15；余下一项使用测试辅助 WebSocket 创建实例后，只进行 hash 跳转，导致应用实例列表未刷新。夹具改为重新载入应用，随后该场景单独通过并连续重复两次通过。不存在将失败场景跳过作为通过的情况。最后额外验证了从舰船页面带入选择后，试算和显式空方案刷新不被链接参数重置。

验证日志位于开发运行目录 `validation/fleet-data-refactor/`。`backend-final.log` 是 407 项组合结果，后续小范围修正单列记录，不声称所有后续修改都重新跑了一次完整组合。
