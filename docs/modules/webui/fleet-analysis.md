# 舰船数据

「舰队管理 → 舰船数据」提供四个平级页面：我的舰船、舰队科技、养成计算、扫描更新。入口为 `/i/:instance/task/FleetAnalysis`，默认我的舰船，`tab=technology`、`tab=mind`、`tab=scan` 选择其他页面。旧科技和心智路由仅跳转。

重构目标与验收清单见 [固定重构计划](fleet-data-refactor-plan.md)。

## 数据原则

正式账号数据分为当前舰船与累计科技。当前舰船逐卡存储，同名副本保留独立 ID；累计科技按舰船种类保存获取、满星、120 级里程碑，状态为已完成、未完成、未核实。删除当前舰船不删除累计科技。图鉴提供身份、形态、阵营、舰种与奖励规则。

扫描、文件导入和截图识别只生成待确认更新。统计读取已确认数据；页面浏览和养成试算不会启动游戏任务或改写正式数据。

## 我的舰船

表格展示名称、副本、等级、突破状态、形态、舰种、阵营、稀有度及核对状态；舰名、等级、突破状态、形态和核对标记可直接原地修改。支持搜索、等级区间、阵营、舰种、重复舰船、待核对筛选和分页。数量区分舰船艘数与种类数。核对状态只显示正常、待核对或等级未知；额外经验未知不产生缺失提示，也不提供经验未知筛选。满星状态在突破状态列单独展示。名称、等级、突破状态、形态、舰种、阵营、稀有度、核对状态均可点击表头切换升降序并显示方向，排序覆盖筛选后的全部记录，切换排序回到第一页，未知值始终置后；阵营按图鉴顺序、稀有度按实际等级排序。不再提供独立排序下拉框。

取消逐条查看／编辑入口与详情侧栏。选择舰名或形态时自动更新身份、舰种、阵营和稀有度；身份不确定时保留待核对。新增行固定在列表前方，删除先标记为待删除并允许恢复；新增、删除、批量标记和各行修改均由顶部唯一的「保存」按钮一次提交。额外经验不展示，原值保留。`?tab=data&ship=ID` 定位并高亮对应副本，兼容旧编辑链接。

满星状态在新增、保存修改和确认扫描／导入时强制写入：所有已知等级低于70级的舰船为未满星；身份确认的常规舰船高于100级为已满星，规则优先于手工值。70级和100级不触发阈值规则；科研、META、原生UR不以高等级判定满星。其余保留已知状态，否则为未知。0级表示等级未知，不按低等级处理。已有数据首次使用时通过一次性事务迁移应用同一规则，后续读取直接使用存储值，不重复推算。当前副本未满星不会清除历史累计满星科技。

编辑草稿保存在当前浏览器会话，关闭和切换页面后仍可恢复。保存检查捕获的数据版本；数据已更新时，需要丢弃旧草稿并重新核对。翻页、筛选和排序不清空草稿；编辑时维持已保存记录的位置，避免输入中行消失或跳动。删除在统一保存后生效，累计科技保留。

## 舰队科技

完整图鉴中每种舰船一行，当前持有数量与最高等级独立于累计里程碑。未持有不等于未获取，缺少证据显示未核实。正式点数、完成数和属性加成使用同一份累计进度，不再切换底账/人工/合并视图。

点击里程碑打开补录或纠错面板，显示点数影响和依据。纠错与当前舰船的已确认事实冲突时，事务拒绝并指向关联舰船。修改经验等无关字段不会重新应用旧推断。阵营科技等级是独立设置，属性区分别显示舰船、阵营和总加成。

满星依赖适用的舰船规则或明确满星记录，不能统一将所有超过 100 级的舰船视作满星。科技全部完成要求三个里程碑都确认完成。

## 养成计算

自动读取当前舰船和累计科技：每个有科技奖励的舰种取现有最高等级的一艘，目标固定为120级。已完成累计120级科技或现有最高等级已到120级的舰种不重复计算，退役后保留的累计完成记录同样有效。身份待核对和无科技奖励舰种不参加自动选择。科技未核实的舰种按当前等级估算费用，明确保留未核实标记。

页面仅展示心智单元、物资及逐舰明细，暂不计算经验。范围和结果随已确认数据自动更新，无需从科技页加入或先手动选船。页面打开期间每5秒检查更新；版本冲突触发自动重新载入。

可按舰种排除本次计算，或展开设置假设等级、已觉醒上限。排除项在最高等级副本变化后继续有效；试算仅作用于原具体副本。觉醒边界默认按尚未觉醒估算，可明确设置已觉醒上限。「恢复自动计算」清空排除与假设，所有调整均不改写舰船和科技事实。

自动计算偏好按实例保存在浏览器 `localStorage`，不沿用旧手动选船方案的固定副本列表；首次继承最高等级副本的旧排除标记。数据库原有经验与旧标记继续保留。费用规则离线保存于 `assets/ship/cultivation.json`，由 `dev_tools/fleet_cultivation_extract.py` 提取并记录来源和 SHA256。

## 扫描更新

页面按开始读取、读取进度、确认更新组织。游戏扫描可设等级范围；文件支持 JSON/CSV/XLSX，截图支持 PNG/JPEG/WebP。导入与截图保留同名副本，不先做最高等级合并。旧 JSON 导入收在折叠项。

当前游戏扫描读取舰船身份、等级等可识别字段，不读取额外经验和满星状态。未读取字段不能覆盖已有人工值。实时阶段依赖调度状态，最近一次成功读取摘要记录来源、时间、读取数量、待核对数量和完整性；它与正式舰船数量分开展示。扫描异常详情仍查看运行日志，不以未读到记录推断成功或退役。

无歧义新增和更新可批量确认；移除单独确认，同名对应不明确时选择具体副本或明确新增。只有满足完整扫描条件才产生缺失移除建议。未处理的结果阻止下一次扫描或导入，避免覆盖。

## 存储与接口

每个实例使用 `config/fleet/<实例名>.sqlite3`。schema v5 保留现有逐卡 ID、累计科技进度、历史依据和待确认差异，将突破次数转换为 `full_star` 三态字段（`true` 已满星、`false` 未满星、`null` 未知），不再保存具体突破次数。原始归档和迁移测试数据副本不作为运行配置自动加载。

| 接口 | 行为 |
| --- | --- |
| `dock.report` | 当前舰船、版本、待确认差异及最近读取摘要 |
| `dock.patch` | 按副本 ID 更新或移除；新增分配新 ID |
| `dock.stageImport` | 将解析后的文件/截图舰船暂存为待确认更新 |
| `dock.review` | 校验正式数据与候选版本，逐项确认或忽略 |
| `dock.configure` | 保存下一次扫描等级范围 |
| `dock.importLegacy` | 显式读取本实例旧 JSON 为待确认更新 |
| `fleetTech.report/patch` | 读取或纠正累计里程碑及阵营等级 |
| `mind.plan` | 按数据版本、具体副本及试算条件只读计算 |
| `mind.import/recognize` | 解析上传内容，不写入正式数据 |

旧 `mind.report/calculate/export` 保留原有算法兼容入口，新页面使用 `mind.plan`。旧 `mind.save` 禁止用无副本身份的清单覆盖数据。旧 `fleetTech.syncMind` 为只读接口。

写操作继续使用登录、实例隔离、生命周期锁和版本校验。游戏扫描只在明确启动任务时执行；测试使用临时配置、数据库和离线截图，不操作真实游戏。
